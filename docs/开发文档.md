# ListMore 开发文档

> 本文档是 ListMore 的单一开发文档入口，面向项目维护者、贡献者以及未来需要重新理解项目的人。
> 文档内容以当前代码和构建配置为准；历史背景中无法由仓库直接确认的部分，会明确标记为待补充。

## 1. 项目概览

ListMore 是一个面向 Fabric 的客户端模组，最初用于把一些适合加入“列表”的辅助功能集中起来。当前功能主要围绕目标识别、实体显示控制、方块与实体渲染辅助、投射物和爆炸预览、原理图预览，以及单次交互限制展开。

项目当前支持以下 Minecraft Fabric 版本：1.21.8、1.21.10、1.21.11、26.1.2、26.2 和 26.3。模组依赖 Fabric Loader、Fabric API 和 MaLiLib；原理图实时预览是可选功能，需要额外安装 Litematica。

项目是客户端模组，`fabric.mod.json` 的环境声明为 `client`。因此，修改渲染、按键、配置界面或客户端 Mixin 时，应优先从客户端生命周期和客户端线程安全的角度检查影响。

## 2. 项目发展回顾

Git 历史可以确认项目从 2026 年 7 月 9 日的初始提交开始，随后逐步形成了现在的功能集合。下面按阶段记录已经能够从提交和代码确认的变化：

1. **初始功能阶段**：项目建立基本的客户端入口、配置系统和若干列表型辅助功能。
2. **实体与熔炉辅助阶段**：加入实体渲染黑名单、实体高亮描边，以及只在单人游戏中工作的无效熔炉输入高亮。
3. **世界交互预览阶段**：加入 TNT 爆炸范围预览和投射物落点预测，并持续调整渲染范围、显示模式和性能。
4. **原理图预览阶段**：加入 Litematica 兼容和原理图文件选择界面的实时预览；之后把预览代码移动到独立的兼容包，并逐步引入后台加载、分区扫描、缓存、拖拽旋转和缩放。
5. **交互限制与多版本阶段**：加入单方块挖掘、单方块放置，完善构建产物命名，并扩展到 26.3。

这些记录描述的是仓库能够验证的开发阶段，不等同于最初想法产生的完整过程。项目创建前的需求来源、哪些功能来自实际使用中的具体问题、哪些方案曾被放弃，后续可以根据个人记忆和旧文件继续补充。不要把无法确认的历史原因写成确定事实。

## 3. 开发环境与构建

### 3.1 目录结构

```text
src/main/java/com/listmore/       共享 Java 源码
    ├── config/                   配置定义、配置界面和选项枚举
    ├── feature/<featureName>/    单个功能的 manager、renderer、input 和模型
    ├── compat/litematica/        可选的 Litematica 原理图预览
    ├── utils/                    无状态共享工具（文件名以 Utils 结尾）
    └── mixin/                    Mixin 补丁、accessor 和 Litematica 兼容补丁
src/main/resources/               模组元数据、Mixin 配置和资源
versions/<版本>-fabric/           各 Minecraft 版本的版本参数
versions/mapping-*.txt            相邻版本之间的预处理映射
build.gradle                      根构建配置和多版本预处理配置
settings.gradle                   动态加载版本子项目
settings.json                     当前参与构建的版本列表
versions/mainProject              共享构建脚本所在的主版本目录
docs/                             项目截图和本开发文档
.github/workflows/build.yml       CI 构建和 Release 发布流程
```

`settings.gradle` 会读取 `settings.json`，为其中每个版本创建 Gradle 子项目；这些子项目都使用 `versions/mainProject` 指定目录中的共享构建脚本。当前主项目是 `1.21.8-fabric`，因此新增或修改构建逻辑时，不能只查看目标版本目录中的文件。

### 3.2 环境要求

仓库的 CI 使用 JDK 25。各版本的 `gradle.properties` 定义了对应的 Minecraft、Fabric Loader、Fabric API、MaLiLib 和 Java 参数。优先使用仓库自带的 Gradle Wrapper，不要依赖系统安装的 Gradle 版本。

Windows 下从项目根目录执行：

```powershell
.\gradlew.bat build
```

Linux 或 macOS 下执行：

```bash
./gradlew build
```

成功后，各版本的 JAR 位于 `versions/<版本>-fabric/build/libs/`。构建通常会同时生成普通 JAR 和 sources JAR；发布时应根据文件名区分，不要把 sources JAR 当成可安装模组。

### 3.3 开发客户端

需要运行开发客户端时，使用对应版本的 Loom 运行任务。具体任务名可能随 Loom 和 Minecraft 版本变化，可先执行：

```powershell
.\gradlew.bat tasks --all
```

再选择目标版本子项目下的客户端运行任务。进入游戏后，优先检查配置界面、按键功能、世界渲染和可选 Litematica 兼容功能。原理图预览需要在测试实例中安装 Litematica，否则只能验证其他功能。

### 3.4 多版本预处理

根 `build.gradle` 中的 `preprocess` 定义了版本链：

```text
1.21.8 -> 1.21.10 -> 1.21.11 -> 26.1 -> 26.2 -> 26.3
```

相邻节点之间通过 `versions/mapping-fabric-*.txt` 提供映射。共享源代码中的 `//#if`、`//#else` 和 `//#endif` 等预处理标记会根据目标版本生成对应源码。涉及 Minecraft API 变化的代码，应尽量沿版本链添加最小分支，并同步更新映射文件，而不是复制出一套完全独立的实现。

新增 Minecraft 版本时，通常需要检查：`settings.json`、对应版本的 `gradle.properties`、根 `build.gradle` 的预处理节点和连接、相邻版本映射文件、资源中的版本条件，以及 CI 的构建产物收集逻辑。

### 3.5 CI、开发构建与发布

`.github/workflows/build.yml` 会在 push、tag 和 pull request 上执行构建。CI 使用完整 Git 历史，以便根构建脚本判断分支。`DEV_BUILD=true` 或当前分支为 `dev` 时，产物名会带有 `-dev` 后缀；产物同时带有 Minecraft 版本后缀，例如 `ListMore-Fabric-1.0.8-mc26.3-dev.jar`。

推送 tag 时，CI 会把所有版本产物收集到 `artifacts/` 并发布到 GitHub Release。发布前应确认版本号、支持版本、依赖版本和 README 内容一致，并至少在代表性版本中启动客户端验证。

## 4. 代码架构与修改入口

### 4.1 初始化链路

入口类是 `com.listmore.ListMore`。它实现 Fabric 的 `ClientModInitializer`，并通过 MaLiLib 的初始化处理器注册：

- `ListMoreConfigs` 配置处理器；
- `CopyTargetIdInputHandler` 按键处理器和按键提供器；
- 投射物、无效熔炉、TNT 三类世界渲染器；
- ListMore 配置界面工厂。

实体描边、实体渲染黑名单、单方块挖掘和单方块放置主要通过 Mixin 接入 Minecraft 或 MaLiLib 的执行路径。修改这些功能时，应先找对应的 Mixin，再沿着被注入的方法确认调用时机和客户端线程。

### 4.2 功能包职责

| 包 | 主要职责 | 说明 |
|---|---|---|
| `config` | 配置定义、持久化、配置界面和选项枚举 | 只放全局配置和配置 UI，不放功能实现 |
| `feature/<featureName>` | 单个功能的全部逻辑：manager、renderer、input、模型 | 新功能默认从这里开始 |
| `compat/litematica` | 可选 Litematica 原理图预览 | 可选依赖，自包含 |
| `utils` | 无状态共享工具 | 只放静态 helper，文件名以 `Utils` 结尾；有状态/有生命周期的类放功能包 |
| `mixin` | 注入 Minecraft、GUI 或 MaLiLib 的现有流程 | accessor 放在使用它的 Mixin 附近；类多了再按功能分组 |
| 根包 | `ListMore`、`ListMoreModMenuApiImpl` | 只放入口点 |

依赖方向：`feature → config/utils`，`utils → Minecraft/MaLiLib`，`compat → utils/config`，`mixin → 所有`。`utils` 不反向依赖功能包；`config` 尽量不依赖功能包，功能专属的选项枚举留在 `config`。当前 `ListMoreConfigs` 对 `EntityRenderBlacklist` 的刷新调用是一个已知例外，后续可以让功能侧自己注册监听器。

### 4.3 配置与兼容

配置由 `ListMoreConfigs` 集中管理，并写入 ListMore 的配置文件。代码保留了旧的 `ohmylist.json` 文件名兼容逻辑，因此修改配置字段或文件名时必须考虑旧用户升级。配置变更后应检查：默认值、序列化名称、配置界面显示、旧配置读取和不同 Minecraft 版本的条件分支。功能专属的选项枚举（如 `TntExplosionPreviewMode`）保留在 `config`，避免 `config` 反向依赖 `feature`。

### 4.4 客户端与服务端边界

大多数功能只需要客户端数据。无效熔炉输入扫描是例外：它需要访问集成服务器的世界数据，因此当前只支持单人游戏。不要在没有确认线程和世界类型的情况下，把这类逻辑扩展到多人服务器；需要多人支持时应重新设计数据来源和同步方式。

## 5. 原理图实时预览流程

原理图预览是项目中最复杂、也最值得单独理解的功能，但相关说明仍集中在本文档中。

1. `GuiSchematicBrowserBaseMixin` 将预览窗口接入 Litematica 的原理图浏览界面。
2. `ListMoreSchematicBrowser` 管理浏览器级别的预览会话和界面布局。
3. `SchematicPreviewSession` 保存当前文件、文件时间戳、变换参数、模型、加载失败状态和渲染管理器。
4. `SchematicPreviewLoader` 负责读取文件，并使用文件线程池和扫描线程池在后台生成预览模型。
5. `SchematicPreviewScanner` 按区块 Section 扫描原理图；扫描结果合并为 `SchematicPreviewModel`。
6. `SchematicPreviewRenderManager` 和 `SchematicPreviewRenderer` 把模型转换为可绘制的网格，并处理视角、缩放、流体、方块实体等显示内容。

加载任务使用共享缓存。相同路径且文件时间戳和大小没有变化时，可以复用已有加载结果；多个会话也可以共享同一后台任务。缓存有数量上限，未使用的加载任务可以取消。

会话使用 generation 计数避免旧任务覆盖新文件的结果。切换文件时，旧请求会被取消，模型和渲染网格被清除，随后启动新请求；后台任务完成后只有在会话仍然打开、generation 仍然匹配且请求没有被替换时，结果才会交给 GUI 线程消费。

`clear()` 用于预览暂时不可见时释放模型和网格，但保留可以复用的渲染后端资源；`close()` 用于会话彻底结束，会进一步释放后端持有的 GPU 资源。修改此处时必须同时检查取消任务、缓存引用、后台线程回调和 OpenGL 资源生命周期。

## 6. 新增或修改功能的工作流程

1. 先确认功能边界：新功能默认在 `feature/<featureName>` 下新建包，把 manager、renderer、input 和模型放进去；可选模组集成放 `compat/<mod>`。
2. 在当前支持的最低版本中实现最小行为，并确认是否涉及其他版本的 API 差异。
3. 将用户可调整的行为放入 `ListMoreConfigs`，避免把可配置项散落在功能类中。
4. 对跨版本差异添加预处理分支，并更新映射文件或版本参数。
5. 对渲染功能检查世界未加载、维度切换、视距变化、第三人称视角和资源释放。
6. 对后台任务检查取消、异常、重复打开、文件快速切换和旧结果覆盖问题。
7. 更新 README 的用户可见功能或支持版本信息，并同步更新本文档中受影响的开发说明。
8. 运行构建；若改动涉及渲染或交互，再启动开发客户端做手工验证。

包结构约定：`feature` 放功能实现，`utils` 只放无状态 `*Utils`，`mixin` 只放补丁。新增类时先确认它属于哪一层，不要把有状态对象塞进 `utils`。

## 7. 验证清单

### 构建

- 所有 `settings.json` 中列出的版本都能完成 `build`。
- 生成的普通 JAR 可以被 Fabric 加载，sources JAR 不被误发布为安装包。
- `dev` 分支产物包含 `-dev`，正式 tag 产物不带该后缀。
- 版本后缀和 README 的支持版本一致。

### 功能

- 配置界面能打开、保存、重新进入后保留设置。
- 列表中的 ID 大小写、空行和无效 ID 不会造成崩溃。
- 世界切换、退出世界和重新进入世界后渲染器状态正常。
- 单方块挖掘和放置每次按键只产生预期的一次交互。
- 未安装 Litematica 时，其他功能仍可正常使用。
- 原理图文件切换、重复选择、加载失败和关闭窗口时没有旧模型或后台任务残留。

### 发布

- 修改说明和 README 已更新。
- 必需前置与可选前置的描述准确。
- 变更没有意外提交本地运行目录、构建缓存或参考工程。
- CI 构建和 Release 产物通过检查。
